# Link rot report - 2026-09-17

**685 dead external URLs, cited 821 times.** A working list, not a narrative. Work down it from the top of each table: the tables are sorted by how many files cite the link, so the first rows are worth the most per fix.

## Why this file exists

The external link check in `link-check.yml` had never run. It passed lychee a flag lychee had removed, so the binary aborted on argument parsing, checked zero URLs, and `fail: false` turned the non-zero exit into a green step in 0.2 seconds. See the CHANGELOG entry for 2026-09-17.

Once it was fixed, a full sweep of all 8,591 unique external URLs in the tree found 701 returning 404, confirmed on a second pass at low concurrency so that rate limiting could not be mistaken for breakage. 16 of them, covering 141 citations, were repaired in the same change. These are the rest.

## How to fix one

Find the vendor's current page for the same subject and replace the URL. Where a live parent section exists, it is listed as **Fallback** below: that is a landing page in the same vendor's docs covering the same area, verified to return 200 on 2026-09-17. It is a floor, not the answer. Prefer finding the actual successor page.

Deliberately **not** applied in bulk, although a script could have: 448 of these have a live parent, and rewriting them all would have turned 685 precise citations into section indexes, made the link checker go green, and removed the only signal that the repair had not really happened. That is the same trade that produced this file.

URLs below are written as code rather than links on purpose, so the link checker does not report this file's contents back as 685 new broken links every Monday.
