# Link rot report

**Every dead external link found on 2026-09-17/18 is now repaired: 783 URLs.** Updated 2026-09-18. This page is the record of what each one was replaced with, so a replacement that looks wrong can be traced and corrected.

## What happened

The external link check in `link-check.yml` had never run (see CHANGELOG 2026-09-17). Once it did, sweeps on 2026-09-17 and 2026-09-18 checked every one of the 8,500+ unique external URLs in the tree for three kinds of death, not just one:

- **Hard 404** - the vendor says the page is gone.
- **Soft 404** - the server answers 200 but the page says "not found". No status-code checker can see these, lychee included. Mostly IBM Cloud docs.
- **Deep link lost to a redirect** - the URL now forwards to a homepage, search page or login wall, so the reader lands somewhere that is not the cited page.

That found **783 dead URLs**, repaired in three passes:

1. **303 URLs (449 citations)** had an obvious successor: the same page at a new address, found in the vendor's own navigation, sitemaps or search.
2. **37 moved links (87 citations)** pointed at dead hosts with a known new home (`home.pearsonvue.com`, `spec.modelcontextprotocol.io`, `forsetisecurity.org`) or only worked through a redirect (AWS doc indexes, product renames such as Vertex AI's).
3. **The last 480 URLs (574 citations)**, whose pages were removed outright, were repaired by hand on 2026-09-18. For each one the link text was read and the closest live page covering the same subject was chosen: the renamed or merged page where one exists (Azure OpenAI into Microsoft Foundry, Cloud DLP into Sensitive Data Protection, Dataproc into Managed Service for Apache Spark, LUIS into conversational language understanding), otherwise the nearest page on the same topic in the same product's docs.

Every replacement was fetched and returned 200 on a page whose title matches the citation, with no redirect to a homepage. Candidates were chosen by reading them, never by a similarity score alone: scores kept matching the wrong product (Open Catalog for Snowflake, Cassandra for Cosmos DB NoSQL, a different Catalyst switch), and every one of those was rejected.

## Three kinds of replacement to know about

- **Retired products point at their successor**, and the link text still names the old product. Where the surrounding notes describe the retired product in detail, the *content* needs revising, not just the link. Examples: QLDB, OpsWorks, LUIS, PaLM, Watson Language Translator and Visual Recognition, Cloud Foundry on IBM Cloud, the AWS Data Analytics and SAP specialty exams.
- **6 links point at a pinned Internet Archive snapshot** because the product is retired with no successor that covers the cited concept (Amazon QLDB's journal, verification and PartiQL reference; AWS redirects all QLDB docs to Aurora). Snapshots never change, so `web.archive.org` is excluded from the weekly link check.
- **The author's own blog post** (`patrickwiloak.com/blog/aws-certification-study-framework-...`) was removed with the blog on 2026-09-05, so its two README mentions were dropped and the site footer now links to the homepage.

URLs are written as code rather than links so the link checker does not report this file back to itself.
